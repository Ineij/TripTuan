# TripTuan 行程总结页改动说明

这份 README 记录本次针对「行程总结 / 保存分享长图」做的改动，方便后续合并、复盘和继续调优。

## 改动目标

原来的总结页更像普通功能页，内容偏机械，缺少用户愿意分享到朋友圈或小红书的情绪点。本次调整的目标是：

- 让总结页从「行程单」变成「旅行回顾报告」。
- 让长图具备社交平台分享欲，而不是普通 UI 截图。
- 深圳和北京使用不同城市主题，避免把参考图里的山地风格照搬到所有城市。
- 插图和亮点必须来自真实行程 POI，不再随意编造地点或图片。
- 文案要根据真实行程数据生成，不能为了好看假装用户吃了美食或去了不存在的地方。

## 主要文件

核心改动集中在：

- `frontend/src/pages/Summary.tsx`
  - 总结页四页卡片
  - 分享弹层
  - 朋友圈长图 `LongPoster`
  - 城市主题配置
  - 行程故事文案生成
- `frontend/src/api/pois.ts`
  - 为 POI 类型补充 `photo` 字段，用于保留原始真实图片。
- `frontend/vite.config.ts`
  - 增加 `/api` 和 `/static` 代理，保证前端开发环境能正确读取后端接口和静态图片。
- `frontend/public/summary-bg/`
  - 总结页和长图使用的城市主题背景图。

## 页面结构

当前总结页保留 4 页，不再使用第五页：

1. 封面页
   - 展示城市、日期、行程点数量、公里数、天数。
   - 走年度报告式视觉，强调「这趟旅行被点亮」。

2. 旅行人格页
   - 根据偏好和实际行程生成旅行人格。
   - 背景使用对应城市图。

3. 足迹地图页
   - 展示本次点亮的行程点。
   - 用抽象路线和高光点位呈现，不做普通地图 UI。

4. 回顾页
   - 使用「启程 / 光影或风味 / 足迹」结构。
   - 如果真实行程里没有美食 POI，就写「收藏城市风景」，不写「品尝城市风味」。

保存分享按钮会打开长图弹层，长图由 `LongPoster` 渲染。

## 城市主题逻辑

主题配置写在 `Summary.tsx` 的 `citySummaryTheme(city)` 里。

目前有两套：

- 深圳
  - 主题：海岸城市
  - 标签：`SEA ROUTE`
  - 视觉关键词：海、日落、港口、海风、湾区水面
  - 背景：`/summary-bg/shenzhen.jpg`

- 北京
  - 主题：古都建筑
  - 标签：`PALACE ROUTE`
  - 视觉关键词：天坛、宫墙、古建筑、暖金色、城市光影
  - 背景：`/summary-bg/beijing.jpg`

注意：北京整体主题是古建筑，但单个 POI 不会强行标成古建筑。比如后端返回滑雪场或博物馆时，卡片只写「北京足迹」，避免胡编。

## 图片来源原则

长图和总结页里的 POI 图片来源顺序是：

1. `place.imageUrl`
   - 已经通过 AIGC 风格化处理的 POI 图片。
2. `place.photo`
   - 原始点评 / POI 图片。
3. `Photo` 组件的 seed fallback
   - 只在没有真实图片时兜底使用。

因此后续如果要让长图更真实、更统一，优先保证后端 POI 返回 `imageUrl` 或 `photo`。

## 文案生成原则

文案由 `buildTripStory(...)` 和 `buildSummary(...)` 生成。

重点规则：

- `hasFood` 只看真实行程里有没有美食 POI。
- 用户偏好里有「爱美食」，但实际行程没有美食时，不会写品尝美食。
- `highlightName` 优先使用真实行程第一站。
- `socialEnding` 根据实际行程类型生成，不再使用过于抽象的「最像你的地方」。

当前示例：

- 深圳只有塘朗山公园、马峦山郊野公园时：
  - 写「收藏了 2 处城市风景」
  - 不写「品尝了 2 种城市风味」

## 长图设计方向

长图不是简单截屏，而是一个连续竖向海报：

- 顶部：城市主视觉图 + 大标题
- 中段：旅行简介 + 数据卡片
- 中段：真实行程亮点卡片
- 中段：Best Stop 高光站点
- 下段：Trip Summary 行程一览
- 底部：下一次再见式 ending

设计参考方向：

- 文艺旅行封面
- 小红书旅行总结长图
- 年度报告式数据叙事
- 城市主题色从首图中提取，而不是固定蓝色或绿色

## 后续调优入口

如果要继续改提示词或文案，优先看这些位置：

- 城市主题和配色：
  - `citySummaryTheme(city)`

- 用户故事 / 旅行人格：
  - `buildTripStory(...)`

- 第四页回顾：
  - `PlacesSlide`

- 分享长图：
  - `LongPoster`

- POI 图片兜底逻辑：
  - `Photo` 组件
  - `SummaryData.places` 的 `imageUrl` / `photo`

## 合并注意事项

- 不建议把 `backend/static/generated/pois/` 下的大量生成图片、日志、表格直接放进 PR。
- 适合合并的是代码、提示词、脚本、少量必要背景图和交付说明。
- 如果需要把批量生成结果给队友，应优先使用 `deliverables/dashscope_csv_image_tool/` 里的离线工具包，而不是把所有生成产物提交进主仓库。
